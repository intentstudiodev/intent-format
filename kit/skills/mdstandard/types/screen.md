# screen · SC · folder `screens/`

> Generated by `mds build-kit` from `schema.json` — do not edit by hand.

A place the user can be: what it is for and what it is made of.

**When to use.** Anything the user navigates to or that hosts its own list of components: a page, a modal, a panel with its own composition. The frame around it (navigation, close, confirm) belongs to a shell, not to the screen; the map's root is a real place such as Home.

**Not to confuse with**
- **component** — Hosts its own component list → screen (modal/panel via appears-as); a piece placed inside places (row, toast, menu) → component; the frame around places → shell.
- **screen-variant** — Same place with another composition or presentation → a variant; a different purpose → a new screen.
- **ia** — A screen never states where it sits or what it leads to; IA maps arrange screens.

**Altitude.** What the place is for and made of — not how users move through it (flows) or where it sits (IA maps).

## Status

`Idea` · `In design` · `Approved` · `In build` · `Live` · `Parked` — Product lifecycle; Parked = set aside from any stage. Movement is free in both directions. Template: `—`. status: — when there is no evidence for any value. Status only with evidence.

## Requirement blocks

Requirement blocks sit in Description & Requirements (and the project's Constraints, and step bodies), after the descriptive prose. Marker `**R<n> · <Preset>**`: n is unique within the file; never reused or renumbered. Default preset here: **GWT** (any preset is legal anywhere; the default is the one templates and agents use first.)

```markdown
**R1 · User story** As a <role>, I want <goal>, so that <benefit>.

**R2 · GWT**
Given <context>
When <event>
Then <observable outcome>

**R3 · EARS** [When <trigger>|While <state>|If <condition>|Where <feature>, [then ]]the system shall <response>.

**R4 · Checklist**
- [ ] <verifiable item>
```

**User story**: so that is mandatory; <role> is the exact name of a role card. · **GWT**: All three keywords present, in this sequence. · **EARS**: Contains "the system shall". · **Checklist**: At least one item. A slot written as — is a declared blind spot (counted).

## Sub-document: screen-variant

Heading `### <Name> · #SV<6 digits>` in ## Variants; anchor `<a id="sv000001"></a>` on the next line.
Optional passport line: `state:` · `appears-as:` · `shell:` · `platform:` · `flag:` (as listed; omit keys at their default).
Optional one prose line, then its own component list as ordered Part lines (or none / —); explicit - Comment: and - Link: (· type: Design) lines may follow.
- A variant holds its whole component list; it never inherits lines from ## Components.
- There is no Default variant: the default is the host's ## Components, and unpinned references resolve to it.
- Variant names are unique within the host; references pin one with · variant: <name or core>.
- Error, empty and loading presentations are ordinary variants.
