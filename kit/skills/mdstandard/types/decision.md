# decision · DC · folder `decisions/`

> Generated by `mds build-kit` from `schema.json` — do not edit by hand.

A question that needs or got a decision: options, outcome and the cards it affects.

**When to use.** Every open question, judgment call or conflict between inputs: record it Open, later Decided with its Outcome. Travels with exports.

**Not to confuse with**
- **comment** — A remark on a card is a comment; a choice between options that changes cards is a decision.
- **flow-step** — A fork is a runtime branch in a journey, not a product decision.

## Front matter

| Key | Required | Values |
|---|---|---|
| `standard` | yes | `MDStandard/1.0` — always the first key |
| `type` | yes | `decision` |
| `id` | yes | `DC000000`-style core (DC + 6 digits) — minted by `mds new`, never by hand |
| `name` | yes | the card name (no `[` `]`); title, references and filename slug derive from it |
| `status` | yes | status vocabulary below, or `—` |
| `state` | no | a State of project.md (one value or a list); omitted = Shared; only when States are declared |
| `origin` | no | `<kb>/<core>` — written by import |
| `x-*` | no | extension keys; kept untouched, always last |

Keys in this order. Unknown = `—` (never quoted); `version`-like values are quoted.

## Status

`Open` · `Proposed` · `Decided` · `Superseded` · `Dropped` — Open/Proposed count as open decisions in health. Template: `Open`. status: — when there is no evidence for any value. Status only with evidence.

## Sections

| Section | Kind | Guidance |
|---|---|---|
| ## Question | required | The question in one or two sentences. |
| ## Options | required | Each option with its trade-off; the recommendation, if any. |
| ## Outcome | required | — while Open or Proposed; the chosen option and why once Decided. |
| ## Affects | required | Every card or sub-document the outcome changes. Default relation: Affects. |
| ## Links | optional | External links: - [title](url) · type: Design\|Code\|Doc\|Source\|Analytics\|Other. Source = evidence (inputs/ file or URL). Default relation: Link. |
| ## Tags | optional | One line of comma-separated tags. |
| ## Comments | optional | Comment cards attached here, one line each; the remark lives in the CM file. Default relation: Comment. |
| ## ⚙ Decisions | generated | Decisions that affect this card. |

Body states: `—` alone = unknown (counted) · `none` alone = verified empty · a final `- —` / `N. —` list item = more items exist but are unknown. Never edit `⚙` sections or the `> ⚙` status line — run `mds regen`.

## Relations written on this type

| Relation | Written in | Targets | Qualifiers | Generated reverse |
|---|---|---|---|---|
| Affects | ## Affects (no prefix) | project, screen, component, shell, userflow, ia, rule, api, feature, edge-case, backend, tech, decision, screen-variant, component-variant, flow-step, shell-variant, role | — | ⚙ Decisions on project, screen, component, userflow, ia, rule, api, feature, edge-case, backend, tech, decision |
| Comment | ## Comments (no prefix) | comment | — | ⚙ Attached to on comment |
| Link | ## Links (no prefix) | URL, or a path to a file in inputs/ | type: Design\|Code\|Doc\|Source\|Analytics\|Other | — |

## Example

```markdown
---
standard: MDStandard/1.0
type: decision
id: DC000001
name: Where do item images live?
status: Open
---
# Where do item images live? · #DC000001
> ⚙ #DC000001V1.0 · V1.0 in-progress

## Question
Should item images be kept in File storage or inside the Main database?

## Options
1. File storage — cheap and fast to serve; needs a cleanup job.
2. Main database — one backup for everything; larger tables.

## Outcome
—

## Affects
- [#BN000003 File storage](../backend/bn000003-file-storage.md)
- [#AP000002 Save item](../apis/ap000002-save-item.md)
```
