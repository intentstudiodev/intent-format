# backend · BN · folder `backend/`

> Generated by `intent-format build-kit` from `schema.json` — do not edit by hand.

A backend node of this product and its connections.

**When to use.** Each server, service, database, storage, integration, repo or environment that serves APIs, keeps data or connects to other nodes.

**Not to confuse with**
- **tech** — The technology a node runs on is tech (Built with); the node itself is backend.
- **api** — Each call is an api card that names this node in Served by.

## Status

`Idea` · `In design` · `Approved` · `In build` · `Live` · `Parked` — Product lifecycle; Parked = set aside from any stage. Movement is free in both directions. Template: `—`. status: — when there is no evidence for any value. Status only with evidence.

Body states: `—` alone = unknown (counted) · `none` alone = verified empty · a final `- —` / `N. —` list item = more items exist but are unknown. Never edit `⚙` sections or the `> ⚙` status line — run `intent-format regen`.

**Why.** `## Why` is optional (absent = nothing to say) here. Its question (choice): *Why this part, this way?* It holds one of: the answer in one or two sentences, optionally ending `[likely]` (follows from inputs) or `[assumed]` (a guess; counted as open) — unmarked means confirmed; `none` or `none — <note>` (no why needed; not counted); `same as #<id>` (another card's why covers it; check follows the link); or `—` (nobody asked yet; counted as why debt). A Why says what the Description does not; a question for the owner goes in the sentence it concerns as `[ask: …]`.

## Requirement blocks

Requirement blocks sit in Description (and the project's Keep in mind, and step bodies), after the descriptive prose. Marker `**R<n> · <Preset>**`: n is unique within the file; never reused or renumbered.

```markdown
**R1 · User story** As a <role>, I want <goal>, so that <benefit>.

**R2 · GWT**
Given <context>
When <event>
Then <observable outcome>

**R3 · EARS** [When <trigger>|While <state>|If <condition>|Where <feature>, [then ]]the system shall <response>.

**R4 · Checklist**
- [ ] <verifiable item>
```

**User story**: so that is mandatory; <role> is the exact name of a role card. · **GWT**: All three keywords present, in this sequence. · **EARS**: Contains "the system shall". · **Checklist**: At least one item. A slot written as — is a declared blind spot (counted).
