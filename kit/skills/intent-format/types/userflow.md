# userflow · UF · folder `userflows/`

> Generated by `intent-format build-kit` from `schema.json` — do not edit by hand.

A journey in one file: typed steps, an ordered step list per variant, and fork wiring.

**When to use.** One flow per main use case or recurring journey; reuse journeys as subflows (⧉ step or attached Connected flow) instead of copying steps.

**Not to confuse with**
- **feature** — A Sub-feature is a capability; the flows homed in it say how the user moves.
- **edge-case** — A named exceptional situation with agreed handling is an edge case whose Where points at the step.
- **rule** — Policy behind a fork branch is cited with · rule: #RL…, never paraphrased.

**Altitude.** How the user moves — not what each place is (screens) or the policy behind a fork (rules).

## Front matter

| Key | Required | Values |
|---|---|---|
| `standard` | yes | `IntentFormat/1.2` — always the first key |
| `type` | yes | `userflow` |
| `id` | yes | `UF000000`-style core (UF + 6 digits) — minted by `intent-format new`, never by hand |
| `name` | yes | the card name (no `[` `]`); title, references and filename slug derive from it |
| `status` | yes | status vocabulary below, or `—` |
| `state` | no | a State of project.md (one value); omitted = Shared; only when States are declared |
| `feature` | no | FT core of this card's home Feature or Sub-feature (one) |
| `users` | no | The user types this card is for: one role card name, or a list; omitted = every user type whose states include its state. |
| `platform` | no | a value of ### Platforms in project.md (or `All`) — Platforms this flow runs on; omitted = all. Its steps are framed per platform. |
| `origin` | no | `<kb>/<core>` — written by import |
| `x-*` | no | extension keys; kept untouched, always last |

Keys in this order. Unknown = `—` (never quoted); `version`-like values are quoted.

## Status

`Idea` · `In design` · `Approved` · `In build` · `Live` · `Parked` — Product lifecycle; Parked = set aside from any stage. Movement is free in both directions. Template: `—`. status: — when there is no evidence for any value. Status only with evidence.

| ## Description | required | The journey's intent, for whom, and its success criteria. |

| ## Links | optional | External links: - [title](url) · type: Design\|Code\|Doc\|Source\|Analytics\|Other. Source = evidence (inputs/ file or URL). Default relation: Link. |
| ## Tags | optional | One line of comma-separated tags. |
| ## Comments | optional | Comment cards attached here, one line each; the remark lives in the CM file. Default relation: Comment. |
| ## ⚙ Entered from | generated | Flows that run or hand off to this flow. |
| ## ⚙ Features | generated | Features that name this card as an explicit touchpoint. |
| ## ⚙ Edge cases | generated | Edge cases that can happen here. |
| ## ⚙ Decisions | generated | Decisions that affect this card. |
| ## ⚙ Shown in | generated | Stepper shells that show this flow. |

Body states: `—` alone = unknown (counted) · `none` alone = verified empty · a final `- —` / `N. —` list item = more items exist but are unknown. Never edit `⚙` sections or the `> ⚙` status line — run `intent-format regen`.

**Why.** `## Why` is required here. Its question (purpose): *Why does this journey exist — what does the user have at the end of it?* It holds one of: the answer in one or two sentences, optionally ending `[likely]` (follows from inputs) or `[assumed]` (a guess; counted as open) — unmarked means confirmed; `none` or `none — <note>` (no why needed; not counted); `same as #<id>` (another card's why covers it; check follows the link); or `—` (nobody asked yet; counted as why debt). A Why says what the Description does not; a question for the owner goes in the sentence it concerns as `[ask: …]`.

## Requirement blocks

Requirement blocks sit in Description (and the project's Keep in mind, and step bodies), after the descriptive prose. Marker `**R<n> · <Preset>**`: n is unique within the file; never reused or renumbered. Default preset here: **EARS** (any preset is legal anywhere; the default is the one templates and agents use first.)

```markdown
**R1 · User story** As a <role>, I want <goal>, so that <benefit>.

**R2 · GWT**
Given <context>
When <event>
Then <observable outcome>

**R3 · EARS** [When <trigger>|While <state>|If <condition>|Where <feature>, [then ]]the system shall <response>.

**R4 · Checklist**
- [ ] <verifiable item>
```

**User story**: so that is mandatory; <role> is the exact name of a role card. · **GWT**: All three keywords present, in this sequence. · **EARS**: Contains "the system shall". · **Checklist**: At least one item. A slot written as — is a declared blind spot (counted).

## Sub-document: flow-step

Heading `### <glyph> <Name> · #FS<6 digits>` in ## Steps; anchor `<a id="fs000001"></a>` on the next line.

| Glyph | Step | Lines | Rule |
|---|---|---|---|
| ○ | Start | Entry 1 · Screen 0..1 · Component 0.. | First line of every step list; exactly one per list. |
| □ | Action | Screen 1 · Component 0.. | The default user step; names exactly one screen (any reference strength). |
| ◇ | Fork | Branch 2.. · Screen 0..1 · API 0..1 · Backend 0..1 · Component 0.. | A decision: the step name is the question; one Branch line per outcome, exactly one · primary. |
| ◎ | Finish | Outcome 1 · Hand-off 0..1 · Screen 0..1 · Component 0.. | An ending, successful or not; a Hand-off continues the journey in another flow. |
| ⧉ | Connected flow | Connected flow 1 | Runs another flow in sequence (a subflow) and continues. |
| ⚡ | System action | API 0.. · Backend 0.. | A product-side step; names the API call or backend node that performs it, never a screen. |
Every step may also carry: Applies rule · Uses API · Connected flow · Comment · Link (except where the step's own line replaces it).
- Steps never store their position: order lives only in step lists, fork wiring only in Branch lines.
- A step may appear in several step lists; it is written once.
- Steps have no variants, state or status of their own.

## Sub-document: flow-variant

Heading `### <Name> (no glyph, no core)` in ## Step list.
Optional passport line: `platform:` · `flag:` (in this order).
Its own full ordered step list (Step lines), drawing on the flow's steps.
- The list under ## Step list itself is the default; variants are alternatives with unique names.
- Every step list (default and variants) starts with the one ○ Start step and SHOULD end on a ◎ Finish or ◇ Fork.
- A list longer than 15 steps SHOULD be split into subflows (⧉ step or attached Connected flow).
