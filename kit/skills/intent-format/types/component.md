# component · CP · folder `components/`

> Generated by `intent-format build-kit` from `schema.json` — do not edit by hand.

A reusable part placed in screens or other components: what it does wherever it appears.

**When to use.** A building block that appears inside places: atom, molecule, organism, or an integration wrapping a third-party capability. The frame around places (top bar, tabs, a stepper, a modal's close and confirm) is a shell, its own type.

**Not to confuse with**
- **shell** — The frame around places, described once and resolved per placement → shell. A part inside places → component.
- **screen** — Navigated to, or hosts its own component list → screen.
- **tech** — The library or service it is made with is tech; the UI part is the component.

**Altitude.** What the part does anywhere — not what one screen uses it for.

## Status

`Idea` · `In design` · `Approved` · `In build` · `Live` · `Parked` — Product lifecycle; Parked = set aside from any stage. Movement is free in both directions. Template: `—`. status: — when there is no evidence for any value. Status only with evidence.

Body states: `—` alone = unknown (counted) · `none` alone = verified empty · a final `- —` / `N. —` list item = more items exist but are unknown. Never edit `⚙` sections or the `> ⚙` status line — run `intent-format regen`.

**Why.** `## Why` is optional (absent = nothing to say) here. Its question (choice): *Why this element, this way?* It holds one of: the answer in one or two sentences, optionally ending `[likely]` (follows from inputs) or `[assumed]` (a guess; counted as open) — unmarked means confirmed; `none` or `none — <note>` (no why needed; not counted); `same as #<id>` (another card's why covers it; check follows the link); or `—` (nobody asked yet; counted as why debt). A Why says what the Description does not; a question for the owner goes in the sentence it concerns as `[ask: …]`.

## Requirement blocks

Requirement blocks sit in Description (and the project's Keep in mind, and step bodies), after the descriptive prose. Marker `**R<n> · <Preset>**`: n is unique within the file; never reused or renumbered. Default preset here: **GWT** (any preset is legal anywhere; the default is the one templates and agents use first.)

```markdown
**R1 · User story** As a <role>, I want <goal>, so that <benefit>.

**R2 · GWT**
Given <context>
When <event>
Then <observable outcome>

**R3 · EARS** [When <trigger>|While <state>|If <condition>|Where <feature>, [then ]]the system shall <response>.

**R4 · Checklist**
- [ ] <verifiable item>
```

**User story**: so that is mandatory; <role> is the exact name of a role card. · **GWT**: All three keywords present, in this sequence. · **EARS**: Contains "the system shall". · **Checklist**: At least one item. A slot written as — is a declared blind spot (counted).

## Sub-document: component-variant

Heading `### <Name> · #CV<6 digits>` in ## Variants; anchor `<a id="cv000001"></a>` on the next line.
Optional passport line: `state:` · `opens-as:` · `platform:` · `flag:` (as listed; omit keys at their default).
Optional one prose line, then its own component list as ordered Part lines (or none / —); explicit - Comment: and - Link: (· type: Design) lines may follow.
- A variant holds its whole component list; it never inherits lines from ## Components.
- There is no Default variant: the default is the host's ## Components, and unpinned references resolve to it.
- Variant names are unique within the host; references pin one with · variant: <name or core>.
- Error, empty and loading presentations are ordinary variants.
