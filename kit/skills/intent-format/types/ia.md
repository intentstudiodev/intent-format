# ia · IA · folder `ia/`

> Generated by `intent-format build-kit` from `schema.json` — do not edit by hand.

One IA map: screens arranged in a hierarchy plus lateral edges — pure arrangement.

**When to use.** One map per arrangement of the product (per State when States change which screens exist); the root is a real place (Home); shells frame subtrees through · shell: on a node.

**Not to confuse with**
- **screen** — A map holds only references; screen facts live on the screen.
- **userflow** — A map says where places sit; a flow says how a user moves through them.

## Front matter

| Key | Required | Values |
|---|---|---|
| `standard` | yes | `IntentFormat/1.2` — always the first key |
| `type` | yes | `ia` |
| `id` | yes | `IA000000`-style core (IA + 6 digits) — minted by `intent-format new`, never by hand |
| `name` | yes | the card name (no `[` `]`); title, references and filename slug derive from it |
| `status` | yes | status vocabulary below, or `—` |
| `state` | no | a State of project.md (one value); omitted = Shared; only when States are declared |
| `platform` | no | a value of ### Platforms in project.md (or `All`) — Platforms this map applies to; omitted = All. |
| `default` | no | `true` · `false` — true = the default map of its state; at most one per state. |
| `origin` | no | `<kb>/<core>` — written by import |
| `x-*` | no | extension keys; kept untouched, always last |

Keys in this order. Unknown = `—` (never quoted); `version`-like values are quoted.

## Status

`Idea` · `In design` · `Approved` · `In build` · `Live` · `Parked` — Product lifecycle; Parked = set aside from any stage. Movement is free in both directions. Template: `—`. status: — when there is no evidence for any value. Status only with evidence.

## Sections

| Section | Kind | Guidance |
|---|---|---|
| ## Description | required | What this arrangement covers and why it exists. |
| ## Why | optional | Optional. Why this arrangement of places? Text (optionally ending [likely] or [assumed]), none[ — note], same as #<id> (another card's why covers it) or —. Absent = nothing to say. |
| ## Parts | required | Indentation tree of screen references, two spaces per level; then ### Lateral with - Edge: lines. Default relation: Node. |
| ## Links | optional | External links: - [title](url) · type: Design\|Code\|Doc\|Source\|Analytics\|Other. Source = evidence (inputs/ file or URL). Default relation: Link. |
| ## Tags | optional | One line of comma-separated tags. |
| ## Comments | optional | Comment cards attached here, one line each; the remark lives in the CM file. Default relation: Comment. |
| ## ⚙ Decisions | generated | Decisions that affect this card. |

Body states: `—` alone = unknown (counted) · `none` alone = verified empty · a final `- —` / `N. —` list item = more items exist but are unknown. Never edit `⚙` sections or the `> ⚙` status line — run `intent-format regen`.

**Why.** `## Why` is optional (absent = nothing to say) here. Its question (choice): *Why this arrangement of places?* It holds one of: the answer in one or two sentences, optionally ending `[likely]` (follows from inputs) or `[assumed]` (a guess; counted as open) — unmarked means confirmed; `none` or `none — <note>` (no why needed; not counted); `same as #<id>` (another card's why covers it; check follows the link); or `—` (nobody asked yet; counted as why debt). A Why says what the Description does not; a question for the owner goes in the sentence it concerns as `[ask: …]`.

## Requirement blocks

Requirement blocks sit in Description (and the project's Keep in mind, and step bodies), after the descriptive prose. Marker `**R<n> · <Preset>**`: n is unique within the file; never reused or renumbered.

```markdown
**R1 · User story** As a <role>, I want <goal>, so that <benefit>.

**R2 · GWT**
Given <context>
When <event>
Then <observable outcome>

**R3 · EARS** [When <trigger>|While <state>|If <condition>|Where <feature>, [then ]]the system shall <response>.

**R4 · Checklist**
- [ ] <verifiable item>
```

**User story**: so that is mandatory; <role> is the exact name of a role card. · **GWT**: All three keywords present, in this sequence. · **EARS**: Contains "the system shall". · **Checklist**: At least one item. A slot written as — is a declared blind spot (counted).
